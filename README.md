# BarsikChat

## Контуры разработки

- Production: `docker compose -f compose.yml up -d` — порт `3000`, рабочая база и загруженные файлы. Пиксельный питомец входит в production-сборку, но включается каждым пользователем отдельно в профиле.
- Development: `docker compose -p barsikchat-dev -f compose.dev.yml up -d` — порт `3100`, отдельная база, отдельное хранилище и включённый dev-флаг питомца.

Dev-контур не использует production-тома и не публикуется через рабочий туннель. Пиксельный питомец включается в профиле и хранит настройку только на текущем устройстве. Интерфейс `window.BarsikPetNative` зарезервирован для будущих Windows/Android-компаньонов; в браузерном dev-режиме используется встроенный экранный вариант.

BarsikChat — самостоятельно размещаемый командный мессенджер для небольшой организации. Клиент работает как адаптивное веб-приложение и устанавливаемая PWA, сервер предоставляет HTTP API, WebSocket-события и Web Push, а данные хранятся в PostgreSQL и локальном файловом томе.

Проект рассчитан примерно на 100 зарегистрированных пользователей и один экземпляр сервера. Звонки и сквозное шифрование в текущую версию не входят.

## Возможности

- регистрация без кода приглашения и вход по email или логину;
- профиль, биография и пользовательский аватар;
- личные чаты и группы до 100 участников;
- единый глобальный поиск по чатам, сообщениям и именам файлов прямо из строки в сайдбаре;
- управление названием, аватаром, участниками и администраторами групп;
- сообщения в реальном времени, форматирование, упоминания, ответы и подсветка ответов;
- закрепление сообщений, множественный выбор, копирование текста/ссылки и удаление у себя или у всех;
- тихая, запланированная, исчезающая и одноразовая отправка;
- редактирование текста, подписи и состава вложений;
- пересылка сообщений и вложений;
- реакции и панель эмодзи;
- изображения, ZIP, RAR и другие файлы до настраиваемого лимита;
- голосовые сообщения и видеокружки;
- закрепление, архив и папки чатов, «Избранное», массовые операции, выход и удаление групп;
- счётчики непрочитанных сообщений, реальные статусы отправки/доставки/прочтения, присутствие и набор текста;
- индивидуальные уведомления чата: на час, до завтра, навсегда или только упоминания;
- всплывающие и системные push-уведомления;
- корректная маршрутизация уведомлений между несколькими окнами;
- установка через браузер и автоматическое обновление PWA;
- Docker Compose, автоматические миграции и health-check.

## Быстрый запуск

Потребуются Docker Desktop либо Docker Engine с Compose.

```bash
cp .env.example .env
docker run --rm node:22-alpine npx --yes web-push generate-vapid-keys
docker compose up -d --build
```

Перед запуском обязательно измените `POSTGRES_PASSWORD`, такой же пароль укажите в `DATABASE_URL`, задайте точный `APP_ORIGIN` и добавьте сгенерированные VAPID-ключи. Затем откройте `http://127.0.0.1:3000`.

Регистрация открыта для любого человека, имеющего ссылку, пока не достигнут `MAX_USERS`. Кода приглашения в проекте нет.

## Разработка и проверки

```bash
npm install
npm run dev
npm run typecheck
npm test
npm run build
npm run smoke
```

`npm run dev` запускает Vite на `http://localhost:5173` и API на `http://localhost:3000`. Для разработки требуется доступная PostgreSQL и корректный `DATABASE_URL`.

`npm run smoke` работает с запущенным сервером. Адреса можно задать через `SMOKE_URL` и `SMOKE_ORIGIN`.

## Структура

- `src/` — React-клиент, компоненты, PWA и service worker;
- `server/` — Express API, сессии, WebSocket и Web Push;
- `migrations/` — последовательные миграции PostgreSQL;
- `public/` — логотип, PWA-иконки и Open Graph-изображение;
- `tests/` — модульные проверки;
- `scripts/smoke.mjs` — сквозная проверка основных сценариев;
- `deploy/` — примеры reverse proxy;
- `legacy-android/` — архив прежней Kotlin-версии, не участвующий в сборке.

## Важные ограничения

- сообщения не имеют сквозного шифрования и доступны администратору сервера через базу данных;
- открытая регистрация требует держать публичную ссылку под контролем;
- загружаемые архивы не проверяются антивирусом;
- email не подтверждается, восстановления пароля и MFA пока нет;
- быстрый Cloudflare Tunnel имеет временный адрес и работает только пока включён компьютер;
- резервные копии необходимо настраивать отдельно.

Для production используйте HTTPS, уникальный пароль PostgreSQL, внешний домен, регулярные резервные копии и инструкции из [docs/SECURITY.md](docs/SECURITY.md).
