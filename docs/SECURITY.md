# Безопасность BarsikChat

Дата последнего аудита: 13 августа 2026 года.

## Модель защиты

BarsikChat защищает данные от неавторизованных посетителей и участников чужих чатов, но не от администратора хоста или человека с доступом к PostgreSQL/volume. Сквозного шифрования и прикладного шифрования базы нет. HTTPS обязателен для защиты данных в сети.

## Реализованные меры

- scrypt с индивидуальной солью для паролей;
- 256-битные session tokens, в базе хранится только SHA-256;
- `HttpOnly`, `SameSite=Lax`, `Secure` cookie на HTTPS;
- проверка текущего членства в защищённых операциях;
- проверка `Origin` для изменяющих HTTP-запросов и Socket.IO handshake;
- CSP, HSTS, `nosniff`, frame restrictions и same-origin resource policy через Helmet/Caddy;
- параметризованные SQL-запросы и Zod-валидация;
- глобальный и authentication rate limit;
- проверка сигнатуры аватаров и блокировка активных HTML/SVG/JS/XML-вложений;
- выдача остальных неизвестных файлов только на скачивание;
- фильтрация Web Push endpoint: только публичный HTTPS без локальных IP/credentials;
- приватные API-ответы не кэшируются;
- Node-процесс работает без root, capabilities и повышения привилегий;
- read-only root filesystem, отдельный writable volume и tmpfs;
- PostgreSQL не публикуется наружу;
- npm и build-инструменты отсутствуют в runtime-образе.

## Результаты аудита

Проверены HTTP-маршруты, SQL, сессии, WebSocket-комнаты, загрузки, пересылка, push, PWA, Docker и зависимости.

Исправлено:

| Важность | Проблема | Исправление |
|---|---|---|
| Высокая | Сокет участника мог оставаться в комнате группы после выхода до reconnect | немедленный отзыв комнаты и разрешения у всех активных сокетов |
| Высокая | Бывший участник мог попытаться изменить/удалить своё старое сообщение по известному ID | edit/delete теперь требуют актуального членства |
| Средняя | Произвольный push endpoint создавал риск SSRF | только безопасные публичные HTTPS endpoint и ограниченные ключи |
| Средняя | Удалённое сообщение могло оставлять скачиваемое вложение | attachment-записи и реакции удаляются; физический файл сохраняется только при существующей пересылке |
| Средняя | Запрос без Origin проходил CSRF-проверку | production-мутации требуют допустимый Origin |
| Средняя | Host из запроса использовался в production HTML metadata | используется настроенный `APP_ORIGIN` |
| Защита в глубину | Runtime содержал ненужный npm с известными CVE | npm/corepack удалены из runtime-слоя |

Автоматические результаты на дату аудита:

- `npm audit`: 0 уязвимостей во всех зависимостях;
- Trivy production image: 0 исправимых High/Critical уязвимостей после hardening;
- TypeScript: без ошибок;
- Vitest: 11/11 тестов;
- smoke: регистрация, WebSocket, Unicode, файлы/архивы, пересылка, реакции, аватар, unread, голос, видеокружки, pin/delete, отзыв доступа и удаление вложений — успешно;
- секреты `.env` не отслеживаются Git и исключены из Docker build context.

На момент проверки подтверждённых неисправленных уязвимостей High/Critical в проверенной конфигурации не обнаружено.

## Известные ограничения и остаточные риски

1. Регистрация открыта. Любой получивший URL может занять аккаунт до `MAX_USERS`; административного подтверждения нет.
2. Нет E2E-шифрования. Администратор сервера может читать сообщения и файлы.
3. Нет MFA, подтверждения email, восстановления пароля и UI управления сессиями.
4. Файлы не проверяются антивирусом. Архивы не распаковываются сервером, но могут быть опасны для получателя.
5. Лимит загрузки ограничивает один запрос, но отдельной пользовательской дисковой квоты нет. Нужен мониторинг свободного места.
6. Rate limit хранится в памяти одного процесса и сбрасывается при restart.
7. Резервные копии не создаются и не шифруются автоматически.
8. Quick Tunnel и домашний компьютер не дают SLA, постоянного адреса и защиты от физического отключения.
9. Web Push передаёт браузерному push-сервису зашифрованный payload и служебные метаданные; содержимое обычных сообщений при этом не является E2E.
10. Single-node presence/Socket.IO не рассчитан на несколько реплик без внешнего адаптера.

## Обязательный production-чеклист

- задайте длинный уникальный `POSTGRES_PASSWORD` и синхронизируйте `DATABASE_URL`;
- используйте точный постоянный HTTPS `APP_ORIGIN`;
- не публикуйте порты PostgreSQL и приложения напрямую;
- храните `.env` только у администратора;
- установите минимально необходимый `MAX_UPLOAD_MB`;
- ограничьте распространение ссылки регистрации;
- настройте ежедневные зашифрованные backup базы и файлов;
- обновляйте base image и зависимости, повторяйте `npm audit` и Trivy;
- контролируйте диск, логи, TLS и health-check;
- используйте антивирус/EDR на рабочих устройствах;
- для чувствительных данных внедрите E2E либо выберите систему с формально проверенным протоколом.

## Повторение проверки

```bash
npm audit
npm run typecheck
npm test
npm run build
docker compose build app
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock aquasec/trivy:latest image --scanners vuln --severity HIGH,CRITICAL --ignore-unfixed chatosnova-app:latest
npm run smoke
```

Сканер использует актуальную на момент запуска базу CVE, поэтому результат со временем может измениться без изменения кода.

## Сообщение об уязвимости

Не публикуйте рабочие секреты, дампы, токены или персональные данные в публичном issue. Передайте администратору BarsikChat описание, затронутый endpoint, воспроизводимые шаги и ожидаемое влияние через закрытый канал организации.
